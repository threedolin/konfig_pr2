# Визуализатор зависимостей Maven — вариант 18

Практическая работа №2 по конфигурационному управлению. Реализованы этапы:

1. **Конфигурация:** CLI с проверкой всех пользовательских параметров.
2. **Сбор данных:** получение и вывод прямых зависимостей Java-пакета из
   Maven-репозитория по HTTP(S).

Для получения зависимостей используются только стандартные модули Python:
`urllib.request` и `xml.etree.ElementTree`. Устанавливать Maven, Gradle или
сторонние библиотеки не требуется.

## Требования и запуск

Нужен Python 3.8 или новее. Сборка и установка зависимостей не требуются.
Команды выполняются из корня проекта:

```sh
./run.sh --package junit:junit:4.13.2 \
  --repository https://repo.maven.apache.org/maven2
```

Результат:

```text
Прямые зависимости junit:junit:4.13.2:
  org.hamcrest:hamcrest-core:1.3 [scope=compile]
  org.hamcrest:hamcrest-library:1.3 [scope=test]
```

Без оболочки `sh`, в том числе в Windows:

```sh
python3 -m src.cli --package junit:junit:4.13.2 \
  --repository https://repo.maven.apache.org/maven2
```

Чтобы автоматически выбрать версию из метаданных репозитория, опустите
версию пакета:

```sh
./run.sh --package junit:junit \
  --repository https://repo.maven.apache.org/maven2
```

Программа выбирает `versioning/release`, затем `versioning/latest`, затем
последнюю запись `versioning/versions/version`. Выбранная версия выводится
в заголовке. Для воспроизводимого результата указывайте версию явно.

## Настройки

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| `--package NAME` | `groupId:artifactId[:version]`, в тестовом режиме — `A`, `ABC` | Обязателен |
| `--repository URL_OR_PATH` | Корень HTTP(S)-репозитория или путь к тестовому файлу | Обязателен |
| `--test-mode {true,false}` | Чтение тестового текстового репозитория | `false` |
| `--output FILE` | Имя SVG-файла для этапа визуализации | `graph.svg` |
| `--max-depth N` | Максимальная глубина для этапа обхода графа | `3` |
| `--help` | Справка и завершение работы | — |

Параметры `--output` и `--max-depth` сохранены и проверяются с этапа 1.
В этапе 2 SVG ещё не создаётся, обход транзитивных зависимостей не
выполняется. Все прямые зависимости выводятся при любой допустимой
глубине, включая `0`. Вывод всех настроек в формате `ключ = значение`
остался в коммите этапа 1; текущая версия выводит зависимости.

Правила проверки:

- Maven-координаты содержат группу, артефакт и необязательную фиксированную
  версию; пробелы и разделители пути в них запрещены.
- URL должен использовать HTTP(S), содержать имя хоста и корректный порт.
  Учётные данные, параметры запроса и фрагменты в URL не допускаются.
- В тестовом режиме имя пакета состоит из `A-Z`, источник — существующий
  читаемый файл в UTF-8.
- `--test-mode` принимает только `true` и `false`.
- Выходной файл должен иметь расширение `.svg`, его каталог должен
  существовать; каталог нельзя использовать как выходной файл.
- Глубина должна быть целым неотрицательным числом.

## Как собираются зависимости

1. Если версия не задана, загружается
   `groupId/as/path/artifactId/maven-metadata.xml`.
2. Загружается POM по пути
   `groupId/as/path/artifactId/version/artifactId-version.pom`.
3. Читаются объявления из `project/dependencies/dependency`, включая
   унаследованные от родительских POM. Родительские POM берутся из того же
   репозитория и кешируются на время запуска.
4. Подставляются свойства `${name}`, `${project.version}` и другие
   координаты проекта/родителя. Версии и область действия могут приходить
   из `dependencyManagement`, включая импортированные BOM.
5. Выводятся координаты, `scope`, а при наличии — `type`, `classifier` и
   `optional=true`. Учитываются все области действия, включая `test` и
   `provided`, а также необязательные зависимости.

Элементы только из `dependencyManagement`, импорт BOM и зависимости
плагинов не добавляются в список прямых зависимостей. POM-файлы самих
найденных зависимостей не скачиваются. Зависимость без версии в объявлении
и в управлении версиями считается ошибкой. Пакет без зависимостей
выводится с отметкой `(нет)`.

Сетевой тайм-аут — 20 секунд на запрос. Циклы родительских POM, циклы
импорта BOM и циклические свойства приводят к понятной ошибке. Глубина
цепочек POM/BOM ограничена 32, подстановок свойств — 64.

Поддерживается статическая модель опубликованных POM: профили Maven и
свойства окружения не активируются, дополнительные репозитории из POM
не используются. Для загрузки POM нужны фиксированные версии;
timestamped SNAPSHOT не разрешаются. Диапазоны версий прямых зависимостей
выводятся как объявлены. Транзитивный граф и SVG относятся к следующим
этапам практической.

Формат реализации основан на официальной документации Maven:
[структура репозитория](https://maven.apache.org/repository/layout.html),
[метаданные](https://maven.apache.org/repositories/metadata.html),
[POM](https://maven.apache.org/pom.html).

## Тестовые примеры без интернета

Текстовый репозиторий `tests/fixtures/repository.txt`:

```text
A: B C
B: C
C:
```

Слева от `:` — пакет, справа — его прямые зависимости через пробел.
Пустые строки и комментарии после `#` пропускаются. Повторяющиеся
зависимости объединяются с сохранением порядка; повторное объявление
пакета считается ошибкой.

```sh
./run.sh --package A --repository tests/fixtures/repository.txt \
  --test-mode true
```

```text
Прямые зависимости A:
  B
  C
```

Для проверки настоящих HTTP-запросов и POM в комплекте есть локальный
Maven-репозиторий. Запустите сервер в отдельном терминале:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory tests/fixtures/maven
```

Затем:

```sh
./run.sh --package org.example:demo --repository http://127.0.0.1:8000
```

```text
Прямые зависимости org.example:demo:2.0:
  org.example:test-helper:4.0 [scope=test]
  org.example:lib:3.2 [scope=compile]
  org.example:managed:5.0 [scope=compile]
  org.example:optional:2.0 [scope=provided, optional=true]
```

Пример без зависимостей:

```sh
./run.sh --package org.example:empty:1.0 \
  --repository http://127.0.0.1:8000
```

```text
Прямые зависимости org.example:empty:1.0:
  (нет)
```

## Обработка ошибок

Ошибки записываются в `stderr`, без частичного списка зависимостей.
Коды завершения: `0` — успех, `1` — ошибка получения или разбора данных,
`2` — ошибка аргументов командной строки.

| Параметр/ситуация | Пример | Результат |
| --- | --- | --- |
| Имя пакета | `--package invalid` | Ожидаются Maven-координаты |
| URL | `--repository ftp://example.org` | Требуется HTTP(S) |
| Режим | `--test-mode maybe` | Допустимы `true` и `false` |
| Выходной файл | `--output graph.png` | Требуется `.svg` |
| Глубина | `--max-depth -1` | Глубина неотрицательна |
| Нет пакета в репозитории | `--package missing:missing:1.0` | Сообщение с URL и `HTTP 404` |
| Недоступен сервер | Недоступный адрес/порт | Сообщение об ошибке загрузки |
| Неверный XML | Повреждённый POM или HTML вместо POM | Сообщение об ошибке XML |
| Нет тестового пакета | `--package Z --test-mode true` | Сообщение, что пакет не найден |

Например, при работающем локальном сервере:

```sh
./run.sh --package missing:missing:1.0 --repository http://127.0.0.1:8000
```

```text
error: не удалось загрузить http://127.0.0.1:8000/missing/missing/1.0/missing-1.0.pom: HTTP 404
```

## Структура и функции

| Файл | Назначение |
| --- | --- |
| `src/cli.py` | Настройки, проверка параметров и вывод результата |
| `src/maven.py` | HTTP-загрузка метаданных/POM и сбор зависимостей |
| `src/pom.py` | Разбор XML и статическая модель зависимостей |
| `src/test_repository.py` | Чтение прямых соседей из текстового файла |
| `tests/test_cli.py` | Проверки параметров, вывода и кодов ошибок |
| `tests/test_maven.py` | HTTP-интеграция, наследование, BOM, свойства и ошибки |
| `tests/test_test_repository.py` | Проверки текстового формата |
| `tests/fixtures/` | Текстовый и Maven-репозитории для примеров и тестов |
| `run.sh` | Запуск `python3 -m src.cli` из каталога проекта |

Функции CLI:

- `non_negative_int` — преобразование и проверка глубины.
- `build_parser` — создание описания аргументов и значений по умолчанию.
- `valid_repository_url` — проверка схемы, хоста, порта и компонентов URL.
- `validate_package`, `validate_repository`, `validate_output` — проверки
  имени пакета, источника данных и выходного файла.
- `main` — запуск выбранного источника, вывод зависимостей и код завершения.

Методы `MavenRepository`:

- `__init__` — сохранение URL и создание кеша.
- `read_xml` — HTTP-запрос с тайм-аутом и проверкой XML.
- `select_package` — разбор координат и выбор версии по метаданным.
- `select_coordinates` — проверка фиксированных координат и кодирование URL.
- `load_model`, `load_parent` — загрузка POM и родителей с проверкой циклов.
- `management` — разрешение управляемых зависимостей и импорта BOM.
- `direct_dependencies` — получение списка прямых зависимостей пакета.

Модуль `pom`:

- `parse_xml`, `text` — чтение XML с пространством имён или без него.
- `expand` — подстановка свойств с обнаружением ошибок и циклов.
- `coordinate_properties` — создание псевдонимов координат проекта и родителя.
- `declarations`, `dependency_key` — чтение объявлений и их идентификация.
- `merge_records`, `make_model` — объединение родительской и дочерней моделей.
- `resolve_dependency` — применение управляемых значений к зависимости.
- `PomModel` — данные модели; `Dependency` — данные прямой зависимости,
  `Dependency.__str__` — форматирование строки результата.
- `RepositoryError` — ошибка источника данных или модели POM.

`test_repository.direct_dependencies` читает текстовый файл и возвращает
прямые зависимости одного тестового пакета без обхода графа.

## Тестирование

```sh
python3 -m unittest discover -s tests -v
```

Тесты работают без интернета: сетевые сценарии используют локальный
HTTP-сервер на свободном порту. Проверяются URL реальных запросов, выбор
версии, пространства имён XML, родительские POM, свойства,
`dependencyManagement` и BOM, все области действия, отсутствие зависимостей,
исключение зависимостей плагинов, ошибки HTTP/XML и циклы моделей.

Также проверяются параметры CLI, явная версия, коды завершения и текстовый
репозиторий. Запуск CLI отдельным процессом проверяет полный путь от
аргументов до вывода зависимостей.
