# Визуализатор зависимостей Maven — вариант 18

Практическая работа №2 по конфигурационному управлению. Реализованы этапы:

1. **Конфигурация:** CLI с проверкой всех пользовательских параметров.
2. **Сбор данных:** получение прямых зависимостей из Maven-репозитория.
3. **Основные операции:** построение транзитивного графа алгоритмом BFS
   без рекурсии, ограничение глубины, обработка циклов и тестовый режим.
4. **Дополнительные операции:** поиск прямых и косвенных обратных
   зависимостей с использованием того же BFS.

Используется только стандартная библиотека Python: `urllib.request` для
HTTP(S), `xml.etree.ElementTree` для POM и `collections.deque` для BFS.
Maven, Gradle и сторонние библиотеки не нужны.

## Требования и запуск

Нужен Python 3.8 или новее. Сборка и установка зависимостей не требуются.
Команды выполняются из корня проекта:

```sh
./run.sh --package junit:junit:4.13.2 \
  --repository https://repo.maven.apache.org/maven2 --max-depth 3
```

Результат:

```text
Граф зависимостей junit:junit:4.13.2 (максимальная глубина: 3):
  junit:junit:4.13.2 [глубина=0]: org.hamcrest:hamcrest-core:1.3, org.hamcrest:hamcrest-library:1.3
  org.hamcrest:hamcrest-core:1.3 [глубина=1]: (нет)
  org.hamcrest:hamcrest-library:1.3 [глубина=1]: org.hamcrest:hamcrest-core:1.3
```

Без оболочки `sh`, в том числе в Windows:

```sh
python3 -m src.cli --package junit:junit:4.13.2 \
  --repository https://repo.maven.apache.org/maven2 --max-depth 3
```

Чтобы выбрать версию из метаданных, опустите её в `--package`:

```sh
./run.sh --package junit:junit \
  --repository https://repo.maven.apache.org/maven2 --max-depth 2
```

Выбор версии: `versioning/release`, затем `versioning/latest`, затем
последняя запись `versioning/versions/version`. Выбранные координаты
отображаются в заголовке. Явная версия обеспечивает воспроизводимость.

## Настройки

| Аргумент | Назначение | По умолчанию |
| --- | --- | --- |
| `--package NAME` | `groupId:artifactId[:version]`, в тестовом режиме — `A`, `ROOT` | Обязателен |
| `--repository URL_OR_PATH` | Корень HTTP(S)-репозитория или путь к тестовому файлу | Обязателен |
| `--test-mode {true,false}` | Чтение тестового текстового репозитория | `false` |
| `--output FILE` | Имя SVG-файла для этапа визуализации | `graph.svg` |
| `--max-depth N` | Максимальное расстояние от корня в рёбрах | `3` |
| `--reverse` | Вывод пакетов, зависящих от выбранного пакета | Выключен |
| `--analysis-root NAME` | Корень графа для ограниченного обратного поиска | Не задан |
| `--help` | Справка и завершение работы | — |

`--max-depth` управляет прямым и обратным обходом. `--reverse` задаётся
без значения. `--analysis-root` применяется вместе с `--reverse` и
обязателен для обратного поиска в Maven. Параметр `--output` проверяется,
но SVG пока не создаётся: визуализация относится к этапу 5.
Текущая версия выводит граф как список смежности; отдельный вывод прямых
зависимостей сохранён в коммите этапа 2.

Правила проверки:

- Maven-координаты содержат группу, артефакт и необязательную фиксированную
  версию. Пробелы и разделители пути запрещены.
- URL должен использовать HTTP(S), содержать имя хоста и корректный порт;
  учётные данные, параметры запроса и фрагменты не допускаются.
- В тестовом режиме имена состоят из `A-Z`, источник — существующий
  читаемый файл UTF-8.
- `--test-mode` принимает только `true` и `false`.
- Выходной файл должен иметь расширение `.svg`, его каталог должен
  существовать. Каталог нельзя использовать как выходной файл.
- Глубина должна быть целым неотрицательным числом.
- `--analysis-root` проверяется по тем же правилам имён, что и `--package`.
  Использование без `--reverse` считается ошибкой аргументов.

## Обход графа

Корень имеет глубину `0`; глубина остальных вершин — длина кратчайшего
пути от корня. Алгоритм использует очередь FIFO и множество уже
обнаруженных вершин:

1. Корень помещается в очередь с глубиной `0`.
2. Вершина извлекается из начала очереди. Если её глубина равна пределу,
   зависимости не запрашиваются.
3. Иначе получаются её прямые зависимости и сохраняются все рёбра.
4. Каждая новая вершина получает глубину родителя плюс один и добавляется
   в конец очереди. Уже обнаруженная вершина повторно не добавляется.
5. Обход заканчивается, когда очередь пуста.

Циклы, петли и ссылки нескольких пакетов на общую зависимость сохраняются
в графе. Каждая вершина раскрывается не более одного раза, поэтому циклы
не приводят к бесконечному обходу. Рекурсивных вызовов в алгоритме обхода
графа нет. Время обхода — `O(V + E)` без учёта получения данных.

Результат выводится в порядке обнаружения вершин BFS:

- `(нет)` — зависимости получены, их список пуст;
- `(предел глубины)` — вершина включена в граф, её зависимости не
  запрашивались. Это не утверждение об отсутствии зависимостей.

При глубине `0` выводится только корень. Для Maven без явной версии могут
загружаться метаданные корня; его POM и прямые зависимости не загружаются.
POM-файлы вершин на предельной глубине также не запрашиваются. Родительские
POM и BOM для раскрываемых вершин могут загружаться как вспомогательные
документы и сами по себе не становятся вершинами графа.

## Тестовый репозиторий

Формат файла: слева от `:` — имя пакета, справа — его прямые зависимости
через пробел. Лист объявляется пустой правой частью:

```text
A: B C
B: C
C:
```

Имена могут состоять из нескольких заглавных латинских букв (`ROOT`,
`SHARED`). Все упомянутые пакеты должны иметь явные объявления, в том
числе листья. Ссылки вперёд, циклы и петли допустимы. Пустые строки и
комментарии после `#` пропускаются; повторные рёбра объединяются с
сохранением порядка. Повторное объявление пакета и ссылка на
необъявленный пакет считаются ошибками.

Файл читается и проверяется один раз перед обходом. Затем используется
тот же BFS, что и для Maven.

### Ограничение глубины

```sh
./run.sh --package A --repository tests/fixtures/repository.txt \
  --test-mode true --max-depth 0
```

```text
Граф зависимостей A (максимальная глубина: 0):
  A [глубина=0]: (предел глубины)
```

При `--max-depth 1`:

```text
Граф зависимостей A (максимальная глубина: 1):
  A [глубина=0]: B, C
  B [глубина=1]: (предел глубины)
  C [глубина=1]: (предел глубины)
```

При `--max-depth 2`:

```text
Граф зависимостей A (максимальная глубина: 2):
  A [глубина=0]: B, C
  B [глубина=1]: C
  C [глубина=1]: (нет)
```

`C` сохраняет глубину `1`, несмотря на дополнительный путь через `B`.

### Транзитивная цепочка

```sh
./run.sh --package A --repository tests/fixtures/text_chain.txt \
  --test-mode true --max-depth 2
```

```text
Граф зависимостей A (максимальная глубина: 2):
  A [глубина=0]: B
  B [глубина=1]: C
  C [глубина=2]: (предел глубины)
```

Пакет `D` находится на глубине `3` и в этот результат не попадает.

### Общая зависимость двух ветвей

```sh
./run.sh --package ROOT --repository tests/fixtures/text_diamond.txt \
  --test-mode true --max-depth 3
```

```text
Граф зависимостей ROOT (максимальная глубина: 3):
  ROOT [глубина=0]: LEFT, RIGHT
  LEFT [глубина=1]: SHARED
  RIGHT [глубина=1]: SHARED
  SHARED [глубина=2]: (нет)
```

Общий пакет `SHARED` раскрывается один раз, оба входящих ребра сохраняются.

### Цикл и петля

```sh
./run.sh --package A --repository tests/fixtures/text_cycle.txt \
  --test-mode true --max-depth 10
```

```text
Граф зависимостей A (максимальная глубина: 10):
  A [глубина=0]: B
  B [глубина=1]: C
  C [глубина=2]: A
```

```sh
./run.sh --package SELF --repository tests/fixtures/text_cycle.txt \
  --test-mode true --max-depth 10
```

```text
Граф зависимостей SELF (максимальная глубина: 10):
  SELF [глубина=0]: SELF
```

### Несвязные компоненты и пакет без зависимостей

```sh
./run.sh --package MAIN --repository tests/fixtures/text_disconnected.txt \
  --test-mode true --max-depth 10
```

```text
Граф зависимостей MAIN (максимальная глубина: 10):
  MAIN [глубина=0]: LEAF
  LEAF [глубина=1]: (нет)
```

Компонента `OTHER → END` и изолированный пакет `ISOLATED` недостижимы
из `MAIN` и не попадают в результат.

```sh
./run.sh --package LEAF --repository tests/fixtures/text_leaf.txt \
  --test-mode true --max-depth 3
```

```text
Граф зависимостей LEAF (максимальная глубина: 3):
  LEAF [глубина=0]: (нет)
```

## Этап 4. Обратные зависимости

Параметр `--reverse` находит пакеты, которые прямо или косвенно зависят
от выбранного `--package`. Исходное ребро `APP → LIB` разворачивается
в `LIB → APP`. После разворота используется функция `build_graph` из
этапа 3: тот же BFS, очередь FIFO, кратчайшие расстояния и обработка циклов.
Рекурсивный обход не используется.

В обратном графе глубина `1` соответствует непосредственным потребителям,
глубина `2` — их потребителям. Выбранный пакет на глубине `0` служит
началом поиска; его строка сама по себе не означает зависимость от себя.
Рёбра циклов и петель сохраняются, вершины раскрываются один раз.

### Полный поиск по тестовому файлу

Файл `tests/fixtures/text_reverse.txt`:

```text
APP: LIB TOOL
CLI: LIB
LIB: CORE
TOOL: CORE
CORE:
ISOLATED:
```

```sh
./run.sh --package CORE --repository tests/fixtures/text_reverse.txt \
  --test-mode true --reverse --max-depth 3
```

```text
Обратные зависимости CORE (максимальная глубина: 3):
Область поиска: весь тестовый репозиторий
  CORE [глубина=0]: LIB, TOOL
  LIB [глубина=1]: APP, CLI
  TOOL [глубина=1]: APP
  APP [глубина=2]: (нет)
  CLI [глубина=2]: (нет)
```

Поиск использует все объявления файла. Поэтому находятся `APP` и `CLI`,
которые недостижимы по исходящим зависимостям `CORE`. Общий потребитель
`APP` выводится один раз с сохранением обоих входящих рёбер.

При замене глубины на `--max-depth 1` остаются прямые потребители:

```text
Обратные зависимости CORE (максимальная глубина: 1):
Область поиска: весь тестовый репозиторий
  CORE [глубина=0]: LIB, TOOL
  LIB [глубина=1]: (предел глубины)
  TOOL [глубина=1]: (предел глубины)
```

При `--max-depth 0` отображается только `CORE` с отметкой предела глубины.
Пакет без потребителей даёт успешный результат с `(нет)`:

```sh
./run.sh --package ISOLATED --repository tests/fixtures/text_reverse.txt \
  --test-mode true --reverse --max-depth 3
```

```text
Обратные зависимости ISOLATED (максимальная глубина: 3):
Область поиска: весь тестовый репозиторий
  ISOLATED [глубина=0]: (нет)
```

### Цикл и петля

```sh
./run.sh --package A --repository tests/fixtures/text_cycle.txt \

```

```text
Обратные зависимости A (максимальная глубина: 10):
```

```sh

```

```text

Область поиска: весь тестовый репозиторий
  SELF [глубина=0]: SELF
```

### Ограничение области поиска

`--analysis-root` выбирает исходный проект. Сначала его прямой граф
строится BFS с заданным `--max-depth`, затем обнаруженные рёбра
разворачиваются и выполняется обратный BFS с тем же пределом глубины.
Результат относится только к собранным рёбрам. Входящие связи от пакетов,
которые не были раскрыты при прямом обходе, в него не попадают.

```sh
./run.sh --package CORE --repository tests/fixtures/text_reverse.txt \
  --test-mode true --reverse --analysis-root APP --max-depth 3
```

```text
Обратные зависимости CORE (максимальная глубина: 3):
Область поиска: граф APP, глубина 3; только найденные рёбра
  CORE [глубина=0]: LIB, TOOL
  LIB [глубина=1]: APP
  TOOL [глубина=1]: APP
  APP [глубина=2]: (нет)
```

`CLI` исключён из области проекта `APP`. Если цель не обнаружена в
ограниченном графе, выводится ошибка, а не пустой список. Например,
при `--analysis-root APP --max-depth 1` пакет `CORE` ещё не найден.
Цель на самой границе глубины допускается.

Для Maven `--analysis-root` обязателен: POM перечисляет зависимости
пакета, но не всех его потребителей в репозитории. Пример для реальных
пакетов:

```sh
./run.sh --package org.hamcrest:hamcrest-core:1.3 \
  --analysis-root junit:junit:4.13.2 \
  --repository https://repo.maven.apache.org/maven2 --reverse --max-depth 3
```

Находятся `junit:junit:4.13.2` и `org.hamcrest:hamcrest-library:1.3`
в пределах графа JUnit. Область поиска указывается в выводе; это не
глобальный список потребителей Maven Central. Для воспроизводимого поиска
версии цели и исходного проекта лучше указывать явно.

## Получение данных Maven

POM загружается по пути
`groupId/as/path/artifactId/version/artifactId-version.pom`.
При необходимости версия корня берётся из
`groupId/as/path/artifactId/maven-metadata.xml`.

Читаются `project/dependencies/dependency`, включая унаследованные
объявления. Поддерживаются родительские POM, свойства `${name}`,
координаты проекта/родителя и `dependencyManagement` с импортом BOM.
Документы кешируются на время запуска. Объявления только из управления
версиями, импорт BOM и зависимости плагинов не добавляются как рёбра.

Вершины идентифицируются полными координатами `groupId:artifactId:version`.
Разные версии одного артефакта остаются разными вершинами. Обход следует
по всем прямым объявлениям, включая `test`, `provided` и `optional`.
Правила распространения областей действия и разрешения конфликтов версий
Maven не реализованы; области действия не выводятся рядом с рёбрами.

Используется статическая модель POM: профили и свойства окружения не
активируются, дополнительные репозитории из POM не используются.
Для раскрытия вершины нужна фиксированная версия; диапазоны версий и
разрешение timestamped SNAPSHOT не поддерживаются.

Сетевой тайм-аут — 20 секунд на запрос. Циклы родительских POM/BOM и
свойств приводят к диагностике. Лимит цепочек POM/BOM — 32, подстановок
свойств — 64; эти ограничения не являются пределом глубины BFS.

Формат Maven описан в официальной документации:
[структура репозитория](https://maven.apache.org/repository/layout.html),
[метаданные](https://maven.apache.org/repositories/metadata.html),
[POM](https://maven.apache.org/pom.html).

Для проверки HTTP без интернета есть локальный Maven-репозиторий.
В отдельном терминале запустите:

```sh
python3 -m http.server 8000 --bind 127.0.0.1 --directory tests/fixtures/maven
```

Затем:

```sh
./run.sh --package org.example:demo --repository http://127.0.0.1:8000 \
  --max-depth 2
```

Пример содержит общий пакет `org.example:shared:1.0` и цикл
`demo → managed → demo`. При глубине `2` общий пакет присутствует на
границе без загрузки его POM; при глубине `3` он раскрывается один раз.

## Ошибки

Диагностика записывается в `stderr`, частичный граф не выводится.
Коды завершения: `0` — успех, `1` — ошибка получения или разбора данных,
`2` — ошибка аргументов командной строки.

| Ситуация | Пример | Результат |
| --- | --- | --- |
| Неверное имя | `--package invalid` в режиме Maven | Ожидаются Maven-координаты |
| Неверный URL | `--repository ftp://example.org` | Требуется HTTP(S) |
| Неверный режим | `--test-mode maybe` | Допустимы `true` и `false` |
| Неверный файл вывода | `--output graph.png` | Требуется `.svg` |
| Неверная глубина | `--max-depth -1` | Глубина неотрицательна |
| Нет области Maven | `--reverse` без `--analysis-root` | Ошибка аргументов до HTTP-запросов |
| Неверное сочетание | `--analysis-root APP` без `--reverse` | Ошибка аргументов |
| Цель вне области | `CORE` вне ограниченного графа `APP` | Ошибка поиска |
| Нет тестового пакета | `Z` при наличии только `A` | Пакет не найден |
| Необъявленная зависимость | `A: B` без строки `B:` | Ошибка ссылки в тестовом файле |
| Нет POM | Отсутствующая версия пакета | Сообщение с URL и `HTTP 404` |
| Недоступен сервер | Недоступный адрес/порт | Ошибка загрузки |
| Неверный XML | Повреждённый POM или HTML вместо POM | Ошибка XML |

Ошибки на транзитивных зависимостях обрабатываются так же, как на корне.
При глубине `0` существование явно заданной версии Maven по POM не
проверяется, поскольку запросы POM не выполняются.

## Структура и функции

| Модуль | Назначение |
| --- | --- |
| `src/cli.py` | Аргументы, валидация и запуск анализа |
| `src/graph.py` | Общий алгоритм BFS и текстовый вывод графа |
| `src/maven.py` | HTTP-загрузка метаданных/POM и адаптер Maven |
| `src/pom.py` | XML, наследование, свойства и управление версиями |
| `src/test_repository.py` | Загрузка и проверка текстового репозитория |
| `tests/` | Тесты CLI, BFS, Maven и текстового формата |
| `tests/fixtures/` | Примеры текстовых графов и Maven-репозитория |
| `run.sh` | Запуск `python3 -m src.cli` из каталога проекта |

Функции CLI:

- `non_negative_int`, `build_parser` — описание и преобразование аргументов.
- `add_analysis_arguments` — опции глубины, обратного поиска и вывода SVG.
- `valid_repository_url` — проверка компонентов URL.
- `validate_package`, `validate_repository`, `validate_output` — проверки
  имени, источника и выходного файла.
- `validate_mode` — проверка режима и имени исходного проекта.
- `collect_graph` — выбор адаптера репозитория и направления поиска.
- `collect_reverse_graph` — подготовка области, разворот и повторное
  использование BFS для обратных зависимостей.
- `main` — обработка ошибок, вывод результата и код завершения.

Граф:

- `DependencyGraph` — корень, предел глубины, словари смежности и глубин,
  множество раскрытых вершин, направление и описание области поиска.
- `build_graph(root, dependency_names, max_depth)` — обход очередью без
  рекурсии; функция `dependency_names` возвращает прямые имена соседей.
- `format_graph` — список смежности в порядке BFS с отметками границы.
- `reverse_adjacency` — разворот рёбер без изменения исходного графа,
  с сохранением изолированных вершин и порядка потребителей.

Методы `MavenRepository`:

- `__init__`, `read_xml` — создание кеша и HTTP-загрузка с проверкой XML.
- `select_package`, `select_coordinates` — выбор версии и проверка координат.
- `load_model`, `load_parent` — загрузка POM и родителей с проверкой циклов.
- `management` — управляемые зависимости и импорт BOM.
- `direct_dependencies` — прямые зависимости с версиями и атрибутами.
- `canonical_name` — фиксированные координаты корня.
- `dependency_names` — прямые координаты соседей для BFS.

Модуль `pom`:

- `parse_xml`, `text` — разбор XML и чтение значений.
- `expand`, `coordinate_properties` — свойства и псевдонимы координат.
- `declarations`, `dependency_key` — объявления и идентичность зависимости.
- `merge_records`, `make_model` — объединение родительской и дочерней моделей.
- `resolve_dependency` — применение управляемых значений.
- `PomModel`, `Dependency` — данные модели и зависимости;
  `Dependency.__str__` — формат прямой зависимости для API этапа 2.
- `RepositoryError` — ошибка данных или модели.

Текстовый репозиторий:

- `_read_records`, `_add_record`, `_validate_references` — чтение, разбор
  записей и проверка всех ссылок.
- `TestRepository.__init__` — однократная загрузка файла.
- `TestRepository.canonical_name` — проверка наличия вершины.
- `TestRepository.dependency_names` — копия списка её прямых зависимостей.
- `TestRepository.adjacency` — независимая копия всего графа для обратного
  поиска, включая потребителей вне исходящего замыкания цели.
- `direct_dependencies` — совместимый интерфейс этапа 2 без обхода графа.

## Тестирование

```sh
python3 -m unittest discover -s tests -v
```

Интернет не требуется: HTTP-проверки используют локальный сервер на
свободном порту. Тесты проверяют наследование и свойства POM, BOM,
ошибки HTTP/XML, параметры CLI и коды завершения, порядок BFS, кратчайшие
глубины, ограничение запросов на границе, циклы, петли, общие зависимости,
несвязные компоненты и листья. Цепочка длиннее лимита рекурсии Python
проверяет независимость обхода от стека рекурсивных вызовов.

Проверки этапа 4 охватывают разворот рёбер, поиск потребителей по всему
файлу, прямые и косвенные связи, циклы и петли, отсутствие потребителей,
ограничение области и глубины. CLI проверяется в обоих режимах, включая
обратный поиск по POM через локальный HTTP-сервер.
